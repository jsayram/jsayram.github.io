VCU’s Microcomputer Systems course taught me how to program, analyze, and debug a microprocessor using assembly language and the C programming language. It also taught me how to interface sensors and input/output devices to a microprocessor, and helped me understand instruction set architectures and the major hardware and software components of a microcomputer.

Abstract

One robot, three challenges.

This project consisted of designing and implementing an embedded system: an autonomous robot capable of navigating through a maze, following a black line drawn on a white surface, and drawing a visually appealing image on a canvas, all using the knowledge and techniques acquired throughout the course. The project deliverables, timelines, constraints, and how each feat was implemented can be followed throughout the page.

Mechanical design

Breadboards as chassis.

For the base of the robot, an acrylic expansion plate with all the necessary mounting holes allowed the design to have many configurations. For the rest of the chassis, four breadboards were used as the structure of the robot, bridged by the microcontroller on top. The two breadboards on the sides allowed for easier connections to the H-bridges and stepper motors. This organized the wire clutter and made a more manageable system that was easy to troubleshoot.

Sensor placement

Putting the reflective sensors as far as possible from the pivoting wheels gives the microcontroller a better reaction time and reduces the chance of overshooting during the line-following and artwork trials. The distance between the sensors depended on the track itself; they were placed 1–3 cm apart to detect discontinuities in the track. For the distance sensors, placing one at a 45° angle at one edge of the chassis and the other facing the front gave a better sense of the maze.

Electrical design

A schematic anyone can follow.

The electrical design was intuitive: the schematic was straightforward and went hand in hand with what was originally planned, building off the previous labs. We took the time to draw a visual schematic that was easy to read and that laid out every component controlled by the microcontroller.

H-bridges

The H-bridges on the sides of the robot are an important part of the system: they drive the stepper motors forward and take up most of the robot’s wired connections. In general we used at least 8 pins to drive both stepper motors, at least 4 pins for the reflectance sensors, and 2 pins for the distance sensors, for a total of 14 pins.

Software architecture

Maze algorithm

The approach was to think about how a human could navigate the maze without opening their eyes: an algorithm that mimics keeping a right hand on one side of the maze’s wall. We used only one distance sensor at a 45° angle. This proved sufficient, and we came up with a simple algorithm that solved the problem successfully.

Software architecture

Line following algorithm

With line following, each reflective sensor has two states: black or white, which can be represented as true or false, ‘1’ or ‘0’. We used 4 sensors to read the line on the floor, denoted as four binary digits: sensor 1, sensor 2, sensor 3 and sensor 4. As the robot follows the line, it continues as long as any of the sensors detects the line, giving 16 possible ways it can see the line. If the robot leaves view of the line (0000), it backs up slightly. This made sure the system stayed on the line at all times. The task was to finish; speed was not a factor we considered.

0110 → Forward Live: sensor byte → motor case

This can be broken down into three logical steps. As the sensors read the conditions in front of them, the value is stored in a byte with each bit representing the status of one sensor. If a bit is 1, the corresponding sensor is over the line; if it is 0, it is not.

For example, if the sensors read ‘0110’ (sensor 1 = 0, sensor 2 = 1, sensor 3 = 1, sensor 4 = 0), the robot sees the line and moves forward. Each sensor combination maps to one of 16 cases. After one case runs, the program loops again and performs the case matching the next reading. If the sensors read 0x0001, the robot sees the line on its far right and corrects itself by moving slightly right and then forward. The same is true for readings like ‘1100’ or ‘0011’. The most extreme cases, ‘1000’ and ‘0001’, mean a turn is needed, and the speed and direction of both motors are adjusted accordingly.

Software architecture

Drawing algorithm

The writing mechanism was designed like a spring in a car: the pen’s spring kept constant pressure on the canvas without too much pressure, and adding weight on top of the pen allowed for a small drawing on the canvas.

For qualification, the task was to draw a simple square bigger than 9” by 9” and smaller than 15” by 15”, ideally about 12”. For the competition the task was to draw a visually appealing image; we chose a balloon because everyone likes balloons.

Although the drawing implementation was simple, the build-up to achieve that simplicity was not easy: motor timing, coordination between the motors, and mechanical placement of the utensil made it challenging. The software implementation in main was fairly straightforward, with the rest following the same logic using different loop timing and motor direction.
